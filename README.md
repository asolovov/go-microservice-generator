GMG is a CLI util used to generate code for a Go microservice based on user configuration and models. It is powered by
`text/template` and AI Agent stack implemented by `github.com/pontus-devoteam/agent-sdk-go`.

The project is at POC stage at the moment. Big idea is to create a universal instrument facilitating Go development
or even generating the whole service for standardized cases. It won't be able to replace a human developer, but it 
should be able to significantly speed up a development process.

## Getting started
### From Repository
Pull repository

```shell
git pull git@github.com:asolovov/go-microservice-generator.git
```

Install dependencies

```shell
make tidy
```

Run example flow

```shell
export AGENT_OPENAIKEY=<your open ai key> 
make run-example
```

It will generate an example service in [/example](./example) directory. Using [example config](./gmg-cfg-example.yaml)

## Features
### Config
User sets configuration in a .yaml file. Example can be seen [here](./gmg-cfg-example.yaml) and 
schema [here](./gmg-cfg-schema.yaml). You can enable and disable specific blocks to be generated and add custom 
requirement for an AI agent.

### Layout
Layout is determined by [templates](./templates). Full scheme that can be generated:

```
.
├── cmd/
│   ├── root/
│   │   └── root.go
│   ├── serve/
│   │   └── serve.go
│   └── <app_name>.go // ENTRY POINT
├── config/
│   ├── init.go
│   └── scheme.go
└── internal/
    ├── service/
    │   ├── service.go
    │   └── cfg.go
    ├── server/
    │   ├── server.go
    │   └── grpcServer/
    │       ├── serverGrpc.go
    │       ├── handlers.go
    │       └── cfg.go
    └── repository/
        ├── repository.go
        └── cfg.go
```

### Models
Main feature of this POC version. There are three types of models in this project:

- `DOMAIN` models - created by user
- `PROTO` models - user creates a `.pb` file that can be generated to `.go` files using `protoc`. AI will generate methods
to parse `PROTO` models to `DOMAIN` models and back
- `DB` models - used to facilitate the work with named methods of `github.com/jmoiron/sqlx` or any other similar libs.
AI will generate the model itself using `.sql` migrations created by user and parsing methods from and to `DOMAIN`.

## Flow
1. Create `go.mod` (or generate it using the util)
2. Create `DOMAIN` models
3. Create `.sql` migrations
4. Create `.pb` files for the microservice GRPC server
5. Setup the `gmg-cfg.yaml` file
6. Run the util and get generated service with model parsing methods.

## Next steps
### Auto fix with AI
Generated code can contain bugs. After the code generation at any point user can run any bugged command (e.g. build) 
with AI Agent mode, so that AI agent can fix it or make a fix proposal.

### Server methods
AI can generate Server methods since they do not contain any business logic, only routing and parsing data.

### Repository methods
AI can generate standard repository methods like add, update, delete and list for a specific database type.

### External services (from .pb)
AI can generate external service implementation using user created .pb files.

### REST server (API microservice)
Most of the API microservice logic is parsing and routing data. All of that can be generated by AI (expect hard cases)

### Unit tests with AI
Parsing methods should be unit tested in the first place. If needed, unit tests can be generated for user-created 
business logic layer
